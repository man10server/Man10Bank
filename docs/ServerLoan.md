# サーバーローン（リボ）仕様書

サーバーがプレイヤーに貸し付けるリボルビングローン（`/mrevo`）の仕様です。
借入・利息・返済・借入枠の計算・延滞時の扱いは、すべて `Man10BankService` が行います。
プラグインはコマンドの受付と表示だけを担当します。

- 対象サービス: [`ServerLoanService.cs`](../../man10bankservice/Man10BankService/Services/ServerLoanService.cs)、[`ServerLoanRepository.cs`](../../man10bankservice/Man10BankService/Repositories/ServerLoanRepository.cs)、[`ServerLoanSchedulerService.cs`](../../man10bankservice/Man10BankService/Services/ServerLoanSchedulerService.cs)
- 対象プラグイン: [`ServerLoanCommand.kt`](../src/main/java/red/man10/man10bank/command/serverloan/ServerLoanCommand.kt)

本書の金額と割合は既定値です。変更できるものは「[設定値](#設定値)」にまとめています。

## 概要

- 借りたお金は銀行口座に入り、残債には毎日利息が付く。
- 週に1回、銀行口座から定期返済が自動で引き落とされる。
- 借入枠は 10万円から始まり、定期返済を期日どおりに重ねると 300万円まで育つ。
- 定期返済に失敗すると延滞になり、借入枠が半減し、新規借入と銀行からの出金・送金が止まる。
- 他のプレイヤーの契約に参加すると、残債・借入枠・延滞の状態をその契約の全員で共有する。

## 用語

| 用語 | 意味 |
|---|---|
| 残債 | 現在の借入残高（`server_loan_tbl.borrow_amount`）。利息を含む |
| 借入枠 | 残債の上限。`/mrevo` では「借入上限」と表示する |
| 定期返済 | 週次で自動的に行われる返済。借入枠の評価対象になる |
| 手動返済 | プレイヤーが `/mrevo pay` で行う返済。早期返済とも呼ぶ |
| 支払額(設定) | プレイヤーが `/mrevo payment` で決める定期返済の希望額 |
| 最低返済額 | 定期返済で必ず引き落とす下限額 |
| 延滞 | 直近の定期返済が失敗のままになっている状態 |
| 契約 | 残債を持つ単位（`server_loan_tbl` の1行）。持ち主を本垢と呼ぶ |
| 参加者 | 他のプレイヤーの契約に参加しているアカウント（`server_loan_member`） |

## 借入

- 「残債 + 今回の借入額」が借入枠以内であれば借りられる。超える場合は `BorrowLimitExceeded`。
- 延滞中は借りられない（`RepaymentOverdue`）。
- 借りたお金は銀行口座に入金される。
- 支払額(設定)が未設定（0 以下）の状態で借りると、「借入額 × 日利 × 14」が支払額として設定される。追加で借りても更新されない。

## 借入枠

借入枠は DB に保存せず、プレイヤーのログを古い順にたどって毎回計算する。

1. 10万円（`MinAmount`）から始める。
2. 定期返済が成功するたびに、「返した額」と「その週の平均残債」の小さいほうの 50%（`GrowthFactor`）だけ増やす。
   ただし1回の増加は、その時点の枠の 10%（`MaxGrowthRate`）まで。
3. 定期返済が失敗するたびに、枠を半分（`FailureCutRate`）にする。
4. 各ステップで 10万円〜300万円（`MinAmount`〜`MaxAmount`）の範囲に収め、1円未満は切り捨てる。

手動返済、延滞分の回収、プレイヤーの資産は借入枠に影響しない。

### その週の平均残債

利息を払わずに枠だけ育てることを防ぐため、返した額のうち「実際に借りて利息が付いていた分」だけを増枠の対象にする。

- 平均残債は、直近7日間に利息が付いた時点の残債を合計し、7 で割ったものである。
- 利息が付かなかった日は 0 として数える。返済の直前に借りた分は、利息が付いていないので数えない。
- 対象にするのは、前回の定期返済（成功・失敗）より後に付いた利息だけである。
- 各時点の残債は、現在の残債からログの増減を逆算して求める。
- 利息停止フラグ（`stop_interest`）が立っているローンは利息が付かないため、枠は育たない。

残債のほうが返済額より大きい通常の借り方では、平均残債は返済額を上回るので、増える額は返した額の 50% のままになる。

### 例：枠が 100,000 円のとき

その週ずっと、返済額以上を借りていた場合。

| その週に返した額 | 返した額の 50% | 上限（枠の 10%） | 増える額 | 新しい枠 |
|---|---|---|---|---|
| 10,000 円 | 5,000 円 | 10,000 円 | 5,000 円 | 105,000 円 |
| 20,000 円 | 10,000 円 | 10,000 円 | 10,000 円 | 110,000 円 |
| 50,000 円 | 25,000 円 | 10,000 円 | 10,000 円 | 110,000 円 |

枠の 20% 以上を返すと上限に当たり、それ以上返しても増え方は変わらない。

20,000 円を借りて定期返済で全額返す場合の、借りていた期間による違い。

| 借りた時期 | 平均残債 | 増える額 | 新しい枠 |
|---|---|---|---|
| 1週間前（利息が7回付いた） | 20,000 円以上 | 10,000 円 | 110,000 円 |
| 返済の前日（利息が1回付いた） | 約 2,857 円 | 約 1,428 円 | 101,428 円 |
| 返済日の利息計算より後（利息が付いていない） | 0 円 | 0 円 | 100,000 円 |

### 育つ速さの目安

常に枠いっぱいまで借りている場合の、300万円に届くまでの定期返済回数。

| 毎週の返済額 | 回数 |
|---|---|
| 残債の 20% 以上 | 36 回（約8か月半） |
| 最低返済額のみ | 39 回（約9か月） |

日利 2% では最低返済額が残債の約 15.9% になるため（「[定期返済](#定期返済)」を参照）、最低返済額だけでも枠は上限に近い速さで育つ。

借りたお金でそのまま全額返す往復をしても、`MaxGrowthRate` により最短で 36 回かかる。
その場合も、毎週、枠の 20% を1週間借りておく必要があり、300万円に届くまでに約 89万円の利息がかかる（日利 2% の場合）。

## 利息

- 毎日、残債 × 日利 2%（`DailyInterestRate`）を残債に加算する（複利）。1円未満は四捨五入する。
  - 返済しない場合、1週間で約 14.9%、30日で約 81% 増える。
- 残債が 0 のローンと、利息停止フラグ（`stop_interest`）が立っているローンには付かない。
- 利息で残債（元本 + 利息）が 1,000万円（`MaxDebtAmount`）を超えることはない。超える分の利息は付けず、残債は上限で止まる。
  - 例：残債 9,900,000 円で利息が 198,000 円になる日は、100,000 円だけ付けて残債を 10,000,000 円にする。
  - 運営の調整などで残債がすでに上限を超えている場合は、利息を付けない。残債を上限まで減らすことはしない。
  - `MaxDebtAmount` を 0 以下にすると、上限なしになる。
- 同じ日に2回実行されても、当日分の利息ログがあるローンはスキップする。

## 定期返済

週に1回、すべてのローンについて銀行口座から引き落とす。

- **引き落とし額**: 支払額(設定)と最低返済額の大きいほう。残債を超える分は引き落とさない。
- **最低返済額**: 次の3つのうち最も大きい額。残債がそれ未満なら残債全額。
  - 残債 × 2%（`MinPaymentRate`）
  - 1万円（`MinPaymentAmount`）
  - 1週間分の利息 + 残債 × 1%（`MinPrincipalRate`）
- **成功**: 残債が減り、借入枠が育つ。
- **残高不足**: 一部だけの引き落としは行わない。失敗として記録され、延滞になる。
- **残債 0**: 何もしない（延滞中の場合は「[延滞の解消](#延滞の解消)」を参照）。

3つ目は、金利を上げても最低返済額だけで残債が減るようにするためのものである。

- 「1週間分の利息」は、現時点の残債に日次の利息計算を7日分適用した合計である。四捨五入と `MaxDebtAmount` の上限を反映する。
- 利息停止フラグが立っているローンは、利息を 0 として計算する。
- 既定の日利 2% では残債の約 15.9% になる。残債 300万円なら、最低返済額は約 47.6万円（利息 約 44.6万円 + 元本 3万円）。
- 日利を約 0.14% 以下にすると 2% のほうが大きくなり、3つ目は効かなくなる。

`/mrevo` の「次回支払額」は、現時点の残債で計算した引き落とし額である。
返済日までに付く利息の分だけ、実際の額が増えることがある。

## 手動返済

- `/mrevo pay <金額>` でいつでも返済できる。残債を超える分は返済されない。
- 最低返済額は適用されない。
- 借入枠は育たない。延滞も解消しない。
- 残高不足の場合はエラーになるだけで、失敗の記録も延滞も付かない。

## 延滞

定期返済が残高不足で失敗すると延滞になる。
延滞は「直近の定期返済のログが失敗である」状態を指す。

### 延滞中の扱い

| 項目 | 扱い |
|---|---|
| 借入枠 | 失敗した時点で半減する。延滞が続いても追加では減らない |
| 新規借入 | 不可（`RepaymentOverdue`） |
| 銀行からの出金 | 残債がある間は不可（`WithdrawBlockedByOverdue`） |
| 送金（送る側） | 同上 |
| 小切手の作成 | 同上（運営小切手は可） |
| 個人間貸付（貸す側） | 同上 |
| 指定ワールドへの進入 | 残債がある間は不可（プラグインの設定による。「[ワールドへの進入制限](#ワールドへの進入制限)」を参照） |
| 入金、送金の受け取り、ローンの返済 | 可 |
| 利息 | 付き続ける |

出金の制限は出金 API 全体に掛かるため、他プラグインからの銀行引き落とし（`BankAPI`）も拒否される。
運営による残高調整（`/bankop take bank`）は、出金リクエストに `ignoreOverdueBlock` を付けるため制限を受けない。

次の週の定期返済も失敗した場合は、その時点で借入枠がさらに半減する。

### 延滞分の回収

延滞中で残債があるローンは、毎日の処理で延滞分を回収する。

- 回収の対象は、失敗した定期返済の額のうち、まだ回収していない分。
- 銀行残高が足りなければ、ある分だけ回収する。残高が 0 のときは何も記録しない。
- 回収では借入枠は育たない。

### 延滞の解消

次のいずれかで延滞が解消され、新規借入ができるようになる。

1. 延滞分の回収で、失敗額を回収しきった（または残債が 0 になった）。
2. 次の定期返済が成功した。
3. 手動返済で完済したうえで、次の定期返済日を迎えた。

1 と 3 では、金額 0 の定期返済成功ログを記録して解消する。借入枠は増えない。

手動返済で完済した場合、出金などの制限は残債が 0 になった時点で解けるが、
新規借入は 3 のとおり次の定期返済日まで再開しない。

### ワールドへの進入制限

プラグインで指定したワールドには、延滞中で残債があるプレイヤーは入れない。
対象ワールドを指定しなければ、この機能は働かない。

対象ワールドは `/bankop overdueworld` で設定する。変更はその場で反映され、`config.yml` に保存される。

| コマンド | 内容 |
|---|---|
| `/bankop overdueworld add [ワールド名]` | 対象に追加する。そのワールドにいる延滞者はその場でキックされる |
| `/bankop overdueworld remove [ワールド名]` | 対象から外す |
| `/bankop overdueworld list` | 対象の一覧を表示する |

ワールド名を省略すると、実行したプレイヤーが今いるワールドが対象になる。
`config.yml` を直接編集してもよい（反映にはプラグインの再読み込みが必要）。

```yaml
overdueWorldBlock:
  worlds: [casino, shop_world]
  message: "あなたは延滞者のためこのエリアには入れません"
```

| 入り方 | 扱い |
|---|---|
| テレポート、ポータル | 移動をキャンセルし、`message` をチャットに表示する |
| ログイン、BungeeCord などのサーバー移動 | 対象ワールドに出現した直後にキックする。理由として `message` を表示する |
| そのほかキャンセルできないワールド移動 | 同上 |

- 延滞状態はサーバーの照会 API（`/overdue`）で確認する。ログイン時、対象ワールドに入ったとき、進入を拒否したときに取り直す。
- テレポートとポータルの判定には直近の照会結果を使う。ログイン後に延滞になった場合は、キャンセルではなく進入後のキックになる。
- 延滞を解消した直後は、1回だけ進入を拒否されることがある。もう一度試せば入れる。
- 照会に失敗したとき（銀行サーバーの停止中など）は制限しない。
- 対象ワールドの中にいる間に延滞になっても、その場ではキックしない。次にログインまたは進入したとき、またはそのワールドが対象に追加されたときに判定する。
- ワールド名は大文字小文字を区別しない。

## 契約の共有

サーバーローンは「契約」の単位で残債を持つ。ふだんは1人が1つの契約を使うが、他のプレイヤーの契約に参加すると、その契約を共有する。
サブアカウントで借りて踏み倒すことを防ぐための仕組みで、別人同士が連帯して借りる用途にも使える。

- 契約の持ち主を「本垢」、参加しているアカウントを「参加者」と呼ぶ。
- 1つの契約に、参加者は何人でも参加できる。
- 1つのアカウントが参加できる契約は1つだけである。
- 参加者がいる本垢は、他の契約に参加できない。参加者を参加先に指定した場合は、その本垢の契約に参加する。

### 共有されるもの

| 項目 | 扱い |
|---|---|
| 残債・借入枠 | 契約で1つ。誰が借りても返しても、同じ残債が増減する |
| 借りたお金 | 借りたアカウントの銀行口座に入る |
| 手動返済 | 返済したアカウントの銀行口座から引き落とす |
| 定期返済 | 本垢の口座から先に引き落とし、足りない分を参加者の口座から、参加が古い順に引き落とす。全員の残高の合計で足りなければ失敗になり、どの口座からも引き落とさない |
| 延滞分の回収 | 定期返済と同じ順で、全員の口座から回収する |
| 延滞中の制限 | 契約が延滞すると、全員が借入・出金・送金などの制限と、ワールドへの進入制限を受ける |
| 支払額(設定) | 契約で1つ。誰でも変更できる |
| ログ・`/mrevo` の表示 | 契約のものを表示する |

### 参加と脱退

1. 参加したいアカウントで `/mrevo link request <本垢>` を実行して申請する。
2. 本垢で `/mrevo link accept <申請者>` を実行して承認すると、共有が始まる。

どちらも、内容の説明が出たあとに同じコマンドをもう一度実行して確定する。

- 承認された時点で、参加者自身の契約の残債は本垢の契約へ合算される。
- 参加している間、参加者自身の契約は残債 0 のまま使われない。借入枠は本垢の契約のものを使う。
- どちらかの契約が延滞している間は、申請も承認もできない。
- 申請は `/mrevo link cancel`（申請者）または `/mrevo link deny <申請者>`（本垢）で取り消せる。
- 脱退は `/mrevo link leave` で行う。契約の残債が 0 のときだけ脱退できる。
- 脱退すると自分の契約に戻る。合算した残債は本垢の契約に残り、元の契約には戻らない。

### 運営による強制リンク

運営は `/bankop serverloan link <参加させるプレイヤー> <本垢> [resetlimit]` で、申請と承認を省いて参加させられる。

- 延滞中でも実行できる。
- 承認待ちの申請がある場合は置き換える。すでに他の契約に参加している場合は、先に解除する。
- `resetlimit` を付けると、参加先の契約の借入枠を初期枠（`MinAmount`）に戻す。申告せずに別アカウントで借りていた場合の罰則として使う。以後の定期返済の成功でまた増える。
- `/bankop serverloan unlink <プレイヤー>` で解除する。契約に残債があっても解除できる。合算した残債は戻らない。
- `/bankop serverloan info <プレイヤー>` で、そのプレイヤーが使っている契約の本垢・参加者・承認待ちの申請を確認できる。

延滞の状態は本垢の契約のものを共有する。参加者自身の契約の延滞は引き継がれないので、延滞しているアカウントがある場合は、そのアカウントを本垢に指定する。

### 連携契約向けの設定

参加者がいる契約にだけ使う設定を用意している。既定では通常の契約と同じ値になる。

- `LinkedMaxAmount`: 借入枠の上限。参加者がいた期間だけ、この上限まで枠が育つ。参加者がいなくなると `MaxAmount` に収め直す。
- `LinkedDailyInterestRate`: 日利。日次の利息、最低返済額に含める1週間分の利息、支払額(設定)の初期値に使う。

## スケジュール

時刻はすべて UTC で判定する。

| 処理 | タイミング | 日本時間 |
|---|---|---|
| 利息の加算、続けて延滞分の回収 | 毎日 02:00（`DailyInterestTime`） | 11:00 |
| 定期返済 | 毎週月曜 03:00（`WeeklyRepayDay` / `WeeklyRepayTime`） | 月曜 12:00 |

スケジューラは `Scheduler:Enabled` が true のインスタンスだけで動く。

## ログ

操作は `server_loan_log` に記録され、`/mrevo log` で表示される。
金額は残債の増減を表す（返済は負数）。

| action | 記録されるとき | 金額 |
|---|---|---|
| `Borrow` | 借入 | 借入額（正） |
| `Interest` | 利息の加算 | 利息額（正） |
| `RepaySuccess` | 定期返済の成功、延滞の解消 | 返済額（負）。延滞の解消は 0 |
| `RepayFailure` | 定期返済の失敗 | 引き落とそうとした額（正）。残債は変わらない |
| `EarlyRepay` | 手動返済 | 返済額（負） |
| `OverdueCollect` | 延滞分の回収 | 回収額（負） |
| `SetBorrowAmount` | 運営による残債の調整、契約への参加で残債を移したとき（参加者自身の契約） | 調整前後の差額 |
| `MemberJoin` | 契約への参加（参加先の契約） | 移ってきた残債（正。無ければ 0） |
| `MemberLeave` | 契約からの脱退（参加していた契約） | 0 |
| `LimitReset` | 強制リンク時の借入枠の初期化 | 0 |

各ログには、次の2つも記録する。この列を追加する前のログでは空のままである。

| 列 | 内容 |
|---|---|
| `actor_uuid` | 操作したプレイヤー。借入と手動返済で記録する。参加・脱退では、参加・脱退したアカウントを記録する。利息・定期返済・延滞分の回収などの自動処理と、運営による調整では空 |
| `debt_after` | 操作後の残債。監査用で、借入枠や延滞の計算には使わない |

ログの `uuid` / `player` は契約の本垢を表す。参加者が借りたり返したりした場合も、本垢の契約のログとして記録する。
定期返済と延滞分の回収のログは契約につき1件で、どの口座からいくら引き落としたかは銀行の入出金ログに残る。

延滞の判定に使うのは `RepaySuccess` と `RepayFailure` だけである。
借入枠の計算では、この2つに加えて、平均残債を求めるために `Interest` の日時と全ログの増減を使う。
`MemberJoin` と `MemberLeave` は枠の上限の切り替えに、`LimitReset` は枠の初期化に使う。

## 設定値

`Man10BankService` の `appsettings.json` の `ServerLoan` セクションで設定する。

| キー | 既定値 | 意味 |
|---|---|---|
| `DailyInterestRate` | 0.02 | 日利（複利） |
| `MinAmount` | 100000 | 借入枠の下限（初期枠） |
| `MaxAmount` | 3000000 | 借入枠の上限 |
| `MaxDebtAmount` | 10000000 | 利息で増える残債（元本 + 利息）の上限。0 以下で上限なし |
| `GrowthFactor` | 0.5 | 定期返済の成功時に、「返した額」と「その週の平均残債」の小さいほうに掛けて枠に加える係数 |
| `MaxGrowthRate` | 0.1 | 1回の増加の上限（その時点の枠に対する割合） |
| `FailureCutRate` | 0.5 | 定期返済の失敗時に枠に掛ける率 |
| `MinPaymentRate` | 0.02 | 最低返済額の割合（残債に対して） |
| `MinPaymentAmount` | 10000 | 最低返済額の固定下限 |
| `MinPrincipalRate` | 0.01 | 最低返済額で、1週間分の利息に上乗せして返す元本の割合（残債に対して）。0 以下にすると、利息を見ずに上の2つだけで決める |
| `LinkedMaxAmount` | 未設定 | 参加者がいる契約の借入枠の上限。未設定なら `MaxAmount` と同じ |
| `LinkedDailyInterestRate` | 未設定 | 参加者がいる契約の日利。未設定なら `DailyInterestRate` と同じ |
| `DailyInterestTime` | 02:00 | 日次処理の時刻（UTC） |
| `WeeklyRepayDay` | Monday | 定期返済の曜日 |
| `WeeklyRepayTime` | 03:00 | 定期返済の時刻（UTC） |

`MinPrincipalRate` を 0 以下にしたうえで、`MinPaymentRate` が週あたりの金利（`DailyInterestRate` × 7）以下だと、最低返済額では残債が減らない。
この場合は起動時に警告ログが出る。

プラグインの `config.yml` では、延滞者の進入制限を設定する。

| キー | 既定値 | 意味 |
|---|---|---|
| `overdueWorldBlock.worlds` | `[]` | 延滞者が入れないワールド名。空なら無効 |
| `overdueWorldBlock.message` | あなたは延滞者のためこのエリアには入れません | 進入を拒否・キックしたときの文言 |

## 既知の制約

- **銀行に入金しないプレイヤーからは回収できない。** 回収元は銀行口座だけで、現金と電子マネーは対象外である。
- **個人間貸付の回収は制限していない。** 貸し手による回収は延滞中でも行われるため、別アカウントと組めば延滞者の銀行残高を移せる。
- **借りたお金でそのまま返しても借入枠は育つ。** 資産を見ないためである。育つ速さは `MaxGrowthRate` で抑えており、育てる分は1週間借りて利息を払う必要がある。
- **利息が付かなかった日があると、その週は枠が育ちにくくなる。** サービスの停止などで日次の利息が実行されなかった日や、残債が `MaxDebtAmount` に達して利息が付かなかった日は、平均残債の計算で 0 として数える。
- **平均残債のルールは過去の履歴にも適用される。** 利息が付く前に返済していた分は増枠の対象から外れるため、既存プレイヤーの借入枠が下がることがある。
- **進入制限の対象ワールドでログアウトした延滞者は、そのサーバーに入れなくなる。** ログインのたびに同じ場所に出現してキックされる。延滞を解消するには、別のサーバーで返済するか、延滞分の回収を待つ必要がある。
- **把握していない別アカウントには効かない。** 契約の共有は、本人の申請か運営の指定があって初めて働く。別アカウントを自動で見つける仕組みはない。
- **共有の相手が本人かどうかは区別しない。** 別人同士でも共有でき、その場合は全員の口座が引き落としの対象になる。誤って強制リンクすると、無関係なプレイヤーの口座から回収される。
- **参加時に合算した残債は元に戻せない。** 解除しても残債は本垢の契約に残る。戻す場合は運営が `/bankop give|take serverloan` で調整する。
- **参加者自身の契約の延滞は引き継がれない。** 延滞しているアカウントを参加者として強制リンクすると、残債は本垢の契約に移るが、延滞の状態は移らない。
- **定期返済が二重に実行されることがある。** 実行済みの記録をメモリにしか持たないため、返済日の実行後に同じ日のうちにサービスを再起動すると、もう一度引き落とされる。
- **利息停止フラグを切り替える手段がない。** `stop_interest` は DB を直接書き換える必要がある。
- **古い定期返済ログには手動返済が混ざっている。** 手動返済を `EarlyRepay` として区別する前の `RepaySuccess` は、借入枠の計算に含まれる。
