# サーバーローン（リボ）仕様書

サーバーがプレイヤーに貸し付けるリボルビングローン（`/mrevo`）の仕様です。
借入・利息・返済・借入枠の計算・延滞時の扱いは、すべて `Man10BankService` が行います。
プラグインはコマンドの受付と表示だけを担当します。

- 対象サービス: [`ServerLoanService.cs`](../../man10bankservice/Man10BankService/Services/ServerLoanService.cs)、[`ServerLoanRepository.cs`](../../man10bankservice/Man10BankService/Repositories/ServerLoanRepository.cs)、[`ServerLoanSchedulerService.cs`](../../man10bankservice/Man10BankService/Services/ServerLoanSchedulerService.cs)
- 対象プラグイン: [`ServerLoanCommand.kt`](../src/main/java/red/man10/man10bank/command/serverloan/ServerLoanCommand.kt)

本書の金額と割合は既定値です。変更できるものは「[設定値](#設定値)」にまとめています。

## 概要

- 借りたお金は銀行口座に入り、残債には毎日利息が付く。
- 週に1回、銀行口座から定期返済が自動で引き落とされる。
- 借入枠は 10万円から始まり、定期返済を期日どおりに重ねると 300万円まで育つ。
- 定期返済に失敗すると延滞になり、借入枠が半減し、新規借入と銀行からの出金・送金が止まる。

## 用語

| 用語 | 意味 |
|---|---|
| 残債 | 現在の借入残高（`server_loan_tbl.borrow_amount`）。利息を含む |
| 借入枠 | 残債の上限。`/mrevo` では「借入上限」と表示する |
| 定期返済 | 週次で自動的に行われる返済。借入枠の評価対象になる |
| 手動返済 | プレイヤーが `/mrevo pay` で行う返済。早期返済とも呼ぶ |
| 支払額(設定) | プレイヤーが `/mrevo payment` で決める定期返済の希望額 |
| 最低返済額 | 定期返済で必ず引き落とす下限額 |
| 延滞 | 直近の定期返済が失敗のままになっている状態 |

## 借入

- 「残債 + 今回の借入額」が借入枠以内であれば借りられる。超える場合は `BorrowLimitExceeded`。
- 延滞中は借りられない（`RepaymentOverdue`）。
- 借りたお金は銀行口座に入金される。
- 支払額(設定)が未設定（0 以下）の状態で借りると、「借入額 × 日利 × 14」が支払額として設定される。追加で借りても更新されない。

## 借入枠

借入枠は DB に保存せず、プレイヤーの定期返済のログを古い順にたどって毎回計算する。

1. 10万円（`MinAmount`）から始める。
2. 定期返済が成功するたびに、返した額の 50%（`GrowthFactor`）だけ増やす。
   ただし1回の増加は、その時点の枠の 10%（`MaxGrowthRate`）まで。
3. 定期返済が失敗するたびに、枠を半分（`FailureCutRate`）にする。
4. 各ステップで 10万円〜300万円（`MinAmount`〜`MaxAmount`）の範囲に収め、1円未満は切り捨てる。

手動返済、延滞分の回収、プレイヤーの資産は借入枠に影響しない。

### 例：枠が 100,000 円のとき

| その週に返した額 | 返した額の 50% | 上限（枠の 10%） | 増える額 | 新しい枠 |
|---|---|---|---|---|
| 10,000 円 | 5,000 円 | 10,000 円 | 5,000 円 | 105,000 円 |
| 20,000 円 | 10,000 円 | 10,000 円 | 10,000 円 | 110,000 円 |
| 50,000 円 | 25,000 円 | 10,000 円 | 10,000 円 | 110,000 円 |

枠の 20% 以上を返すと上限に当たり、それ以上返しても増え方は変わらない。

### 育つ速さの目安

常に枠いっぱいまで借りている場合の、300万円に届くまでの定期返済回数。

| 毎週の返済額 | 回数 |
|---|---|
| 残債の 20% 以上 | 36 回（約8か月半） |
| 残債の 14% | 51 回（約1年） |
| 残債の 10% | 70 回 |
| 残債の 5% | 130 回 |
| 最低返済額のみ | 261 回 |

借りたお金でそのまま全額返す往復をしても、`MaxGrowthRate` により最短で 36 回かかる。

## 利息

- 毎日、残債 × 日利 0.1%（`DailyInterestRate`）を残債に加算する。1円未満は四捨五入する。
- 残債が 0 のローンと、利息停止フラグ（`stop_interest`）が立っているローンには付かない。
- 同じ日に2回実行されても、当日分の利息ログがあるローンはスキップする。

## 定期返済

週に1回、すべてのローンについて銀行口座から引き落とす。

- **引き落とし額**: 支払額(設定)と最低返済額の大きいほう。残債を超える分は引き落とさない。
- **最低返済額**: 「残債 × 2%（`MinPaymentRate`）」と「1万円（`MinPaymentAmount`）」の大きいほう。
  残債がそれ未満なら残債全額。
- **成功**: 残債が減り、借入枠が育つ。
- **残高不足**: 一部だけの引き落としは行わない。失敗として記録され、延滞になる。
- **残債 0**: 何もしない（延滞中の場合は「[延滞の解消](#延滞の解消)」を参照）。

`/mrevo` の「次回支払額」は、現時点の残債で計算した引き落とし額である。
返済日までに付く利息の分だけ、実際の額が増えることがある。

## 手動返済

- `/mrevo pay <金額>` でいつでも返済できる。残債を超える分は返済されない。
- 最低返済額は適用されない。
- 借入枠は育たない。延滞も解消しない。
- 残高不足の場合はエラーになるだけで、失敗の記録も延滞も付かない。

## 延滞

定期返済が残高不足で失敗すると延滞になる。
延滞は「直近の定期返済のログが失敗である」状態を指す。

### 延滞中の扱い

| 項目 | 扱い |
|---|---|
| 借入枠 | 失敗した時点で半減する。延滞が続いても追加では減らない |
| 新規借入 | 不可（`RepaymentOverdue`） |
| 銀行からの出金 | 残債がある間は不可（`WithdrawBlockedByOverdue`） |
| 送金（送る側） | 同上 |
| 小切手の作成 | 同上（運営小切手は可） |
| 個人間貸付（貸す側） | 同上 |
| 入金、送金の受け取り、ローンの返済 | 可 |
| 利息 | 付き続ける |

出金の制限は出金 API 全体に掛かるため、他プラグインからの銀行引き落とし（`BankAPI`）も拒否される。
運営による残高調整（`/bankop take bank`）は、出金リクエストに `ignoreOverdueBlock` を付けるため制限を受けない。

次の週の定期返済も失敗した場合は、その時点で借入枠がさらに半減する。

### 延滞分の回収

延滞中で残債があるローンは、毎日の処理で延滞分を回収する。

- 回収の対象は、失敗した定期返済の額のうち、まだ回収していない分。
- 銀行残高が足りなければ、ある分だけ回収する。残高が 0 のときは何も記録しない。
- 回収では借入枠は育たない。

### 延滞の解消

次のいずれかで延滞が解消され、新規借入ができるようになる。

1. 延滞分の回収で、失敗額を回収しきった（または残債が 0 になった）。
2. 次の定期返済が成功した。
3. 手動返済で完済したうえで、次の定期返済日を迎えた。

1 と 3 では、金額 0 の定期返済成功ログを記録して解消する。借入枠は増えない。

手動返済で完済した場合、出金などの制限は残債が 0 になった時点で解けるが、
新規借入は 3 のとおり次の定期返済日まで再開しない。

## スケジュール

時刻はすべて UTC で判定する。

| 処理 | タイミング | 日本時間 |
|---|---|---|
| 利息の加算、続けて延滞分の回収 | 毎日 02:00（`DailyInterestTime`） | 11:00 |
| 定期返済 | 毎週月曜 03:00（`WeeklyRepayDay` / `WeeklyRepayTime`） | 月曜 12:00 |

スケジューラは `Scheduler:Enabled` が true のインスタンスだけで動く。

## ログ

操作は `server_loan_log` に記録され、`/mrevo log` で表示される。
金額は残債の増減を表す（返済は負数）。

| action | 記録されるとき | 金額 |
|---|---|---|
| `Borrow` | 借入 | 借入額（正） |
| `Interest` | 利息の加算 | 利息額（正） |
| `RepaySuccess` | 定期返済の成功、延滞の解消 | 返済額（負）。延滞の解消は 0 |
| `RepayFailure` | 定期返済の失敗 | 引き落とそうとした額（正）。残債は変わらない |
| `EarlyRepay` | 手動返済 | 返済額（負） |
| `OverdueCollect` | 延滞分の回収 | 回収額（負） |
| `SetBorrowAmount` | 運営による残債の調整 | 調整前後の差額 |

借入枠の計算と延滞の判定に使うのは `RepaySuccess` と `RepayFailure` だけである。

## コマンド

| コマンド | 内容 |
|---|---|
| `/mrevo` | 借入額、支払額(設定)、次回支払額、日利息、借入上限、前回・次回返済日を表示 |
| `/mrevo borrow <金額>` | 借入（確認つき） |
| `/mrevo pay <金額>` | 手動返済 |
| `/mrevo payment <金額>` | 支払額(設定)を変更 |
| `/mrevo log [ページ]` | ログを表示 |
| `/bankop give\|take\|set serverloan <player> <金額>` | 運営による残債の調整 |

運営が残債を調整すると、支払額(設定)は「調整後の残債 × 日利 × 14」に上書きされる。

## API

ベースパスは `/api/ServerLoan/{uuid}`。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/` | ローン情報 |
| POST | `/borrow` | 借入（本文 `{ "amount": number }`） |
| POST | `/repay?amount=` | 手動返済 |
| POST | `/payment-amount?paymentAmount=` | 支払額(設定)の変更 |
| POST | `/borrow-amount?amount=` | 残債の上書き（運営用） |
| GET | `/borrow-limit` | 借入枠（`{ "limit": number }`） |
| GET | `/payment-info` | 次回返済日、1日あたりの利息、次回支払額 |
| GET | `/logs?limit=&offset=` | ログ |

サーバーローンに固有のエラーコードは次のとおり。いずれも 409 を返す。

| コード | 意味 |
|---|---|
| `BorrowLimitExceeded` | 借入枠を超える借入 |
| `RepaymentOverdue` | 延滞中の借入 |
| `WithdrawBlockedByOverdue` | 延滞中の出金・送金・小切手作成・個人間貸付 |

## 設定値

`Man10BankService` の `appsettings.json` の `ServerLoan` セクションで設定する。

| キー | 既定値 | 意味 |
|---|---|---|
| `DailyInterestRate` | 0.001 | 日利 |
| `MinAmount` | 100000 | 借入枠の下限（初期枠） |
| `MaxAmount` | 3000000 | 借入枠の上限 |
| `GrowthFactor` | 0.5 | 定期返済の成功時に、返した額に掛けて枠に加える係数 |
| `MaxGrowthRate` | 0.1 | 1回の増加の上限（その時点の枠に対する割合） |
| `FailureCutRate` | 0.5 | 定期返済の失敗時に枠に掛ける率 |
| `MinPaymentRate` | 0.02 | 最低返済額の割合（残債に対して） |
| `MinPaymentAmount` | 10000 | 最低返済額の固定下限 |
| `DailyInterestTime` | 02:00 | 日次処理の時刻（UTC） |
| `WeeklyRepayDay` | Monday | 定期返済の曜日 |
| `WeeklyRepayTime` | 03:00 | 定期返済の時刻（UTC） |

`MinPaymentRate` が週あたりの金利（`DailyInterestRate` × 7）以下だと、最低返済額では残債が減らない。
この場合は起動時に警告ログが出る。

## 既知の制約

- **銀行に入金しないプレイヤーからは回収できない。** 回収元は銀行口座だけで、現金と電子マネーは対象外である。
- **個人間貸付の回収は制限していない。** 貸し手による回収は延滞中でも行われるため、別アカウントと組めば延滞者の銀行残高を移せる。
- **借りたお金でそのまま返しても借入枠は育つ。** 資産を見ないためで、育つ速さは `MaxGrowthRate` で抑えている。
- **定期返済が二重に実行されることがある。** 実行済みの記録をメモリにしか持たないため、返済日の実行後に同じ日のうちにサービスを再起動すると、もう一度引き落とされる。
- **利息停止フラグを切り替える手段がない。** `stop_interest` は DB を直接書き換える必要がある。
- **古い定期返済ログには手動返済が混ざっている。** 手動返済を `EarlyRepay` として区別する前の `RepaySuccess` は、借入枠の計算に含まれる。
